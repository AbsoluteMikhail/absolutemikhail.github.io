# 2. Как игра разговаривает со звуком

Разберём модель на шагах персонажа. Названия ниже — придуманный учебный пример, не имена готовых ассетов Gyms.

Игра знает, когда нога коснулась земли и по какой поверхности идёт персонаж. Аудиосистема знает, какие звуки подходят этому действию и как их воспроизводить.

```text
Unreal: произошло касание земли
  → задать Surface = Metal для персонажа
  → передать Speed = 420
  → отправить событие Play_Footstep
Wwise: выбрать и воспроизвести настроенный вариант
```

В этой схеме важно сначала передать контекст, а потом запустить событие. Иначе шаг может использовать значение поверхности от предыдущего контакта.

## Пять терминов на одном примере

| Термин | Смысл | Пример |
| --- | --- | --- |
| **Event** | Команда аудиосистеме; внутри могут быть действия воспроизведения, остановки и другие | `Play_Footstep` запускает настроенное поведение шага |
| **Switch** | Дискретный вариант контекста, обычно для конкретного игрового объекта | `Surface = Metal` у одного персонажа, `Surface = Wood` у другого |
| **State** | Состояние общего аудиоконтекста | `GameMode = Combat` меняет предусмотренные настройки микса |
| **Game Parameter / RTPC** | Число из игры и связь этого числа со свойствами звука | Скорость влияет на заданную кривую громкости или другой параметр |
| **SoundBank** | Подготовленные данные Wwise для исполнения | Игра получает события, структуры и необходимые ссылки на медиа; часть медиа может храниться отдельно |

RTPC расшифровывается как Real-Time Parameter Control. Полезно различать само число — Game Parameter — и то, как его связали со свойством звука. Передача скорости не даст слышимого эффекта, если на стороне аудиопроекта ничего к ней не привязано.

Определения и области действия можно сверить в материалах Audiokinetic: [What are Game Syncs?](https://www.audiokinetic.com/en/public-library/2024.1.8_8898/?id=what_are_game_syncs&source=WwiseFundamentalApproach) и [Understanding the Scope of Game Syncs](https://www.audiokinetic.com/en/learn/videos/tczh9xbyyza/?course=wwise251&lesson=7). Game Parameter может задаваться глобально или для отдельного объекта. Эта глава объясняет модель; привязанные к версии кнопки добавим после практического прохода.

## Источник и слушатель

Для пространственного звука нужны источник — emitter — и слушатель — listener. Источник отвечает на вопрос «откуда звучит», слушатель — «относительно кого слышим». Глобальный интерфейсный сигнал и шаг персонажа в мире могут использовать разные способы воспроизведения.

Поэтому полезно спрашивать не только «какое событие отправили», но и «для какого объекта». Одинаковые события у разных персонажей должны получать правильные позиции и параметры. В готовом Gyms сначала исследуем существующую настройку; добавлять ещё одного слушателя наугад не нужно.

## Что хранится в каком проекте

Есть два связанных проекта. `Gyms.wproj` открывается в Wwise Authoring. `Gyms.uproject` открывается в Unreal. Звук, слышимый в редакторе Wwise, ещё не доказывает, что игра получила свежие данные.

Упрощённый рабочий цикл такой:

```text
исходное аудио и настройки Wwise
  → генерация SoundBanks
  → данные доступны интеграции Unreal
  → игровое событие вызывает звук
  → проверка в игре
```

Банк не следует представлять как ZIP со всеми WAV. Для воспроизведения важны и метаданные, и медиа, и соответствие версии звукового движка. Если настройка изменилась только в Authoring, старые подготовленные данные могут продолжить звучать по-старому. Разделение структур и медиа описано в [Loading Banks](https://www.audiokinetic.com/library/2024.1.5_8803/?id=soundengine__banks__loading.html&source=SDK); конкретную схему загрузки за нас пока обслуживает интеграция Gyms.

## О чём договариваются разработчик и звуковик

Для каждого взаимодействия достаточно короткой карточки:

| Вопрос | Пример договорённости |
| --- | --- |
| Когда отправляем событие? | При контакте ноги с землёй, а не каждый кадр |
| На каком объекте? | На персонаже, который сделал шаг |
| Что передаём заранее? | Тип поверхности и текущую скорость |
| Какие значения допустимы? | Перечень поверхностей и диапазон скорости с единицами |
| Кто проверяет результат? | Разработчик проверяет вызов и данные; звуковик — поведение и микс; итог слушают в игре |

Это предотвращает типичную ситуацию: один человек передаёт скорость от 0 до 1, а другой ждёт сантиметры в секунду.

## Проверка понимания

В игре два персонажа стоят на разных поверхностях. Что удобнее для поверхности: общий State или Switch на каждом объекте? В нашей модели — Switch. А начало боя, которое должно изменить общий микс, естественнее описывать общим состоянием.

Это учебная договорённость, а не единственная допустимая архитектура. Главное — уметь объяснить, кому принадлежит значение и кто его меняет.
