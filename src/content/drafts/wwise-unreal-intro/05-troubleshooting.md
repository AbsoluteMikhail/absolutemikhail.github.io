# 5. Сборка упала или звука нет

Большой красный лог легко воспринимать как одну поломку. В установке Gyms могут независимо ломаться сборка Unreal, подготовка WAV и генерация банков. Начинаем с первой содержательной ошибки конкретного этапа.

Ниже — сообщения из приложенной исходной заметки. Они сохранены как практический кейс; это не результаты установки, выполненной при написании курса.

## Ветка 1. SDK не попал в проект

```text
Unable to instantiate module 'WwiseAuthoring':
Wwise ThirdParty is not installed.
Unable to find "...\Unreal\Plugins\WwiseSoundEngine\ThirdParty\include/AK/AkWwiseSDKVersion.h" file.
```

Сборщик не находит необходимый файл SDK **внутри интеграции проекта**. Это может произойти даже при установленном Wwise Authoring.

Проверь сначала `SDK\include\AK\AkWwiseSDKVersion.h` в установленном Wwise, затем `Unreal\Plugins\WwiseSoundEngine\ThirdParty\include\AK\AkWwiseSDKVersion.h` в Gyms. Сверь выбранные версии и наличие Windows-библиотек.

Если SDK отсутствует уже в установке Wwise, добавь его через изменение компонентов этого выпуска. Затем при закрытом Unreal повтори корректную установку или изменение интеграции через Launcher, чтобы она получила соответствующие зависимости. Если SDK есть в Wwise, но нет в Gyms, сосредоточься на интеграции проекта и её журнале.

Признак исправления — нужный заголовок и библиотеки присутствуют, сборка проходит этот этап. Создание пустого заголовка, отключение WwiseNiagara и копирование SDK случайной версии проблему не решают. Ручная установка SDK возможна только как отдельный маршрут по документации конкретной интеграции.

## Ветка 2. Генератор не нашёл NumPy

```text
ModuleNotFoundError: No module named 'numpy'
```

Это ошибка Python, не компилятора. Проверь в том же окне cmd, откуда запускается setup:

```bat
where python
python -c "import sys; print(sys.executable)"
python -m pip --version
```

Для согласованного маршрута с Python 3.13:

```bat
python -m pip install "numpy==2.2.6"
python -c "import numpy; print(numpy.__version__)"
```

Если импорт работает, можно отдельно проверить генератор из корня Gyms:

```bat
cd /d "C:\WwiseLabs\Gyms"
python WwiseProject\GenerateProjectWavFiles.py
```

Это диагностический повтор после ошибки. При обычном прохождении повторять вручную то, что делает setup, не нужно.

После прерванной генерации скрипт может пропустить уже существующий, но неполный WAV: он проверяет существование пути. Открой подозрительный файл в аудиоредакторе и проверь чтение и длительность. При подтверждённом повреждении перемести **только этот сгенерированный файл** в резервную папку и запусти генерацию снова. Всю `Originals` удалять нельзя.

## Следствие: отсутствующий исходник и неисправный банк

```text
MissingOriginalFile: ShortMedia_3.wav
BankIsMissingFiles
```

Первое сообщение указывает на недоступный исходный медиафайл. Второе сообщает о проблеме комплектности банка. В описанном кейсе цепочка такая:

```text
нет NumPy → генерация WAV не выполнена
  → отсутствует ShortMedia_3.wav
  → генерация SoundBanks сообщает об отсутствии файлов
```

Проверь `WwiseProject\Originals\SFX\ShortMedia_3.wav`, исправь генератор, затем повтори генерацию банков — например, повторным setup после устранения причин. Успех — исходник читается и соответствующие ошибки исчезают из результата генерации.

В другом проекте `MissingOriginalFile` может быть вызвана переименованием, неверной ссылкой или потерянным исходником. NumPy не является универсальным лекарством. И установка NumPy никак не заполняет SDK внутри Unreal-проекта.

## Ещё несколько коротких проверок

| Симптом | Куда смотреть | Как подтвердить исправление |
| --- | --- | --- |
| Не найден компилятор или Windows SDK | Visual Studio Installer, C++ workload, версии MSVC/SDK; лог `%LOCALAPPDATA%\UnrealBuildTool\Log.txt` | Сборщик находит toolchain и завершает сборку |
| Не находятся `.py` или `.uproject` | Рабочая папка должна быть корнем Gyms, рядом с setup | `dir setup_Windows.bat` и `dir Unreal\Gyms.uproject` находят файлы |
| Не запускается WwiseConsole | Значение `WWISEROOT` и реальный файл `Authoring\x64\Release\bin\WwiseConsole.exe` | `dir` находит exe выбранного выпуска |
| Открывается Microsoft Store вместо Python | `where python`, PATH и адрес выбранной установки | `python -c "import sys; print(sys.executable)"` показывает нужный exe |
| pip сообщает об успешной установке, но NumPy не импортируется | Совпадает ли Python у установки пакета и запуска setup | Импорт работает через тот же `python` |
| Ошибки API или версии проекта | Полные версии Integration, SDK, Authoring, UE и SHA Gyms | Собрана документированно совместимая связка |

При конфликте нескольких Python сначала выясни, какой exe выбирается. Исправляй адрес нужной установки или используй отдельное окружение осознанно; отключать все системные псевдонимы и удалять другие Python подряд не требуется.

## Редактор работает, но тишина

Проверяй от простого к конкретному:

1. Запущен ли именно нужный пример и выполнено ли его действие? Пребывание в меню не обязано сопровождаться звуком.
2. Выбран ли правильный аудиовыход Windows, не выключен ли звук приложения в микшере?
3. Что пишет **Output Log** Unreal в момент действия? Сохрани первую ошибку Wwise вместе с именем события или медиа.
4. Завершилась ли генерация банков? Путь, куда они записаны, должен совпадать с путём, который читает интеграция.
5. Связан ли Unreal именно с `WwiseProject\Gyms.wproj` и используются ли согласованные версии?

В этой ревизии общий каталог банков проходит через папку `Unity`; это проверенная особенность Gyms, а не указание установить Unity Editor.

Только после этого имеет смысл исследовать эмиттер, listener и игровую логику. Настройка WAAPI, добавление случайных компонентов и переустановка всего Unreal не являются обязательными шагами первого звука.

## Практика

В логе одновременно видны отсутствующий `AkWwiseSDKVersion.h` и `No module named 'numpy'`. Сколько независимых причин уже известно? Две. Исправление только одной не делает установку рабочей целиком.

Сохрани для разбора: точные версии, SHA Gyms, название этапа, первую содержательную ошибку и несколько строк перед ней. Так следующий заход начинается с проверяемых данных.
