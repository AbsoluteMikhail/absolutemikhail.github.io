## Готовим компоненты и состояние

Создаём отдельный Actor Blueprint **BP_AlarmLights** в Content/FromZero/Blueprints/World. Первую лампу сохраняем как самостоятельный пример. В новом классе добавляем Box Collision и три Point Light под общим корнем. Разносим светильники так, чтобы различать их на карте; используем Movable и выключаем Visible по умолчанию.

Зона делает overlap с Pawn и не блокирует проход. Для этой встречи проверяем одного управляемого персонажа, который начинает игру снаружи зоны. Случай, когда в зону одновременно входят несколько персонажей, пока не разбираем.

Добавляем только нужные переменные:

| Переменная | Тип и назначение |
| --- | --- |
| AlarmActive | Boolean — сигнализация запущена |
| LightsEnabled | Boolean — текущая фаза света |
| BlinkInterval | Float, Instance Editable — положительный интервал таймера, например 0,5 секунды |
| Lights | Массив ссылок на Point Light Component — наши три компонента |
| BlinkTimer | Timer Handle — ссылка для остановки созданного таймера |

В BeginPlay собираем Lights через **Make Array**, перетаскивая в граф ссылки на три компонента. Это ссылки на части одного Actor, а не поиск всех ламп в мире. У каждого экземпляра BP_AlarmLights будут свой массив, состояние и таймер.

## Выносим действие в свою функцию

Создаём функцию **SetLightsEnabled** с входом **Enabled** типа Boolean. В ней записываем Enabled в переменную LightsEnabled и через **ForEachLoop** вызываем **Set Visibility** для каждого элемента Lights. В New Visibility передаём Enabled, в Target — текущий Array Element.

В BeginPlay после заполнения массива вызываем SetLightsEnabled(false). Затем временно вызываем функцию с true и false, чтобы проверить весь набор. После проверки возвращаем выключенное начальное состояние.

На этом примере сравним входной параметр функции, переменную состояния объекта и ссылку на компонент. Наша функция включает или выключает все лампы сразу. Теперь не придётся копировать три одинаковые цепочки в каждое событие.

## Повторяем действие по таймеру

Добавляем собственное событие **BlinkStep**. Оно вызывает SetLightsEnabled, передавая **NOT LightsEnabled**. Один вызов меняет фазу света.

Добавляем собственные события запуска и остановки:

- **StartAlarm:** через Branch проверяем AlarmActive. При уже запущенной сигнализации повторно её не запускаем. Проверяем BlinkInterval > 0; при неверном значении выводим понятное сообщение и выходим. Затем устанавливаем AlarmActive = true, запускаем **Set Timer by Event** с BlinkStep, BlinkInterval и включённым Looping. Return Value сохраняем в BlinkTimer.
- **StopAlarm:** вызываем **Clear and Invalidate Timer by Handle** для BlinkTimer, сбрасываем AlarmActive и вызываем SetLightsEnabled(false). После выхода таймер должен остановиться, а все лампы — погаснуть.

:::tip Цикл и повторение во времени
ForEachLoop перебирает компоненты при одном вызове нашей функции. Интервал между переключениями задаёт таймер. Не пытаемся получить мигание бесконечным WhileLoop или вставкой Delay в обычный цикл перебора.
:::

В функцию мы вынесли повторяющееся действие и передаём ей параметры. Собственные события позволяют отдельно вызывать нужное поведение по имени. Таймер в этом примере привязываем к событию BlinkStep. Заодно коротко отмечаем ограничение обычных Blueprint-функций: внутри них не размещают Delay и другие latent-узлы. Собирать цепочки ожиданий на этом занятии не требуется.

## Подключаем персонажа и проверяем

Event ActorBeginOverlap вызывает StartAlarm, Event ActorEndOverlap — StopAlarm. У зоны и капсулы персонажа включены Generate Overlap Events. Пока работаем с одной зоной и одним персонажем: так проще проследить состояние сигнализации и выполнение графа.

Размещаем экземпляр в TestLevel, компилируем, сохраняем и запускаем Play. Перед запуском попробуйте предсказать, будут ли лампы гореть после нескольких вызовов BlinkStep и что произойдёт, если выйти из зоны в середине мигания.

Проверяем:

- До входа все лампы выключены; внутри зоны они вместе меняют фазу.
- После выхода свет выключается и больше сам не включается.
- Повторный вход снова запускает мигание без ускорения и лишних таймеров.
- Два экземпляра с разными BlinkInterval работают независимо.
- Пустой массив не даёт ошибок; неверный интервал не запускает сигнализацию.

Если результат не совпал, смотрим AlarmActive, LightsEnabled, содержимое Lights и сохранённый BlinkTimer. Для диагностики используем Print String и breakpoint на BlinkStep, затем убираем лишний вывод. Причину ищем в состоянии и цепочке выполнения.

## Самостоятельная практика на встрече

Добавьте самостоятельно четвёртый Point Light в Lights и измените BlinkInterval у второго экземпляра. Функцию и события оставьте общими. Объясните, почему ещё одна лампа не требует копии графа.

Для этой задачи достаточно Branch и ForEachLoop. Sequence, Gate, DoOnce, Switch и другие узлы будем вводить на следующих механиках, когда они понадобятся.

## Домашнее задание — бегущий огонь

Сделайте вариант сигнализации, в котором **за один шаг горит одна лампа**, затем следующая, а после последней снова первая. Используйте тот же массив, таймер и функцию общего выключения; добавьте целочисленный индекс текущей лампы. Подготовьте отдельный вариант Blueprint, сохранив рабочую сигнализацию.

Проверка: не менее трёх ламп проходят полный круг; выход из зоны останавливает таймер и выключает всё; повторный вход начинает последовательность с первой лампы. Пустой массив обрабатывается до обращения по индексу, а единственная лампа остаётся единственной активной. Смена порядка элементов массива меняет порядок огней.

В этом задании потренируемся работать с индексом, хранить состояние и использовать уже собранные части. Готовый граф бегущего огня на встрече разбирать не будем — попробуйте собрать его сами.
