# Правила работы над Absolute Mikhail

Этот файл задаёт постоянные правила для работы над сайтом `gamepunk.ru`. Следовать актуальной задаче пользователя; при работе в подкаталоге учитывать его локальный `AGENTS.md`. Хранить здесь устойчивые договорённости, а не историю задач и временные отчёты.

## Как работать с пользователем

- Общаться по-русски, коротко и по делу. Перед заметной работой сообщать, что собираешься сделать; по ходу объяснять существенные решения и найденные ограничения.
- Доводить запрос до готового и проверенного результата. Обычные обратимые решения внутри задачи принимать самостоятельно; не останавливаться ради подтверждения уже порученной работы.
- Уточнять только то, что существенно меняет результат и нельзя понять из контекста. Пока ответ не получен, выполнять независимую часть работы.
- Если предложенное решение ухудшает удобство, скорость или поддержку сайта, объяснить конкретную проблему и предложить вариант лучше. Не соглашаться автоматически.
- В финале сообщать, что изменено, что проверено и что осталось непроверенным. Не выдавать предположения, успешную сборку или намерение за проверку в браузере и состоявшуюся публикацию.

## Что это за сайт

- Персональное портфолио Михаила Ефремова / Absolute Mikhail: игровой и коммерческий опыт, проекты, отзывы и менторинг по Unreal Engine. Помогать посетителю оценить опыт, посмотреть работы и связаться с автором.
- Основной язык — русский; названия проектов, технологий и профессиональных ролей сохранять в принятом написании.
- Сайт также служит личным музеем автора: сохранять биографию, эксперименты, ранние и замороженные проекты. Длинная страница допустима; улучшать ритм и подачу, не сокращать историю ради продаж. Яркость поддерживать реальными изображениями, типографикой и красно-оранжевыми акцентами.
- Стек: React 18, TypeScript, Vite, React Router, Tailwind CSS, Framer Motion, Lucide и существующие UI-компоненты. Сайт статический, размещается на GitHub Pages; серверная сборка используется для пререндеринга.
- Использовать npm и `package-lock.json`, как в текущем CI. Не менять менеджер пакетов, стек и зависимости попутно с небольшой задачей.

## Где искать и менять

| Что | Где |
| --- | --- |
| Маршруты и клиентский запуск | `src/App.tsx`, `src/main.tsx` |
| Страницы и секции | `src/pages/`, `src/components/` |
| Тексты, опыт, отзывы, предложения менторинга | `src/content/` |
| Каталоги проектов и контактные ссылки | `src/constants/` |
| Палитра, типографика, общие стили | `src/index.css`, `tailwind.config.ts` |
| Изображения, импортируемые в код | `src/assets/` |
| Файлы с постоянными публичными URL | `public/` |
| SEO и генерация HTML / sitemap | `src/constants/routeMetadata.js`, `src/components/RouteMetadata.tsx`, `src/entry-server.tsx`, `scripts/prerender.mjs` |
| Тесты и публикация | `src/test/`, `vitest.config.ts`, `.github/workflows/deploy.yml` |

- Перед правками смотреть `git status` и затронутые файлы. Сохранять чужие незакоммиченные изменения; не откатывать и не переформатировать их ради своей задачи.
- Искать через `rg`, начиная с конкретных каталогов: например, `rg --files src scripts public`. При поиске от корня явно исключать `AbsoluteAcademySource/`, зависимости, сборки и временные каталоги, в том числе при использовании `--hidden` и `--no-ignore`.
- Редактировать исходники. `dist/` и `dist-ssr/` создаются сборкой; ручные исправления в них не являются решением.
- Сохранять UTF-8 и точный регистр путей: локальная Windows может пропустить ошибку, которая сломает сборку на Linux.

## Код и архитектура

- Сначала находить существующий компонент или способ решения и продолжать его. Выделять переиспользуемые части там, где есть повторение или самостоятельная ответственность; не строить универсальную систему ради одного блока.
- Данные редактировать в их существующем источнике, а отображение — в компоненте. Не размножать цены, ссылки, описания проектов и сведения об авторе по JSX.
- Для новых импортов из `src` использовать `@/`; для объединения условных Tailwind-классов — существующий `cn` из `src/lib/utils.ts`.
- Повторяющееся оформление кнопок, заголовков и плашек брать из `src/components/ui/`; варианты и примеры описаны в `src/components/ui/README.md`. Общие изменения вносить в компонент или функцию стилей, а отступы и компоновку конкретной секции оставлять в месте использования.
- Типизировать новые props и данные. Не скрывать проблему через `any`, `@ts-ignore`, отключение правил или ослабление конфигурации ради зелёной проверки.
- Сохранять ленивую загрузку страниц. Тяжёлые сцены, проигрыватели и библиотеки не должны попадать на главную без необходимости.
- Код, участвующий в пререндеринге, должен работать без `window`, `document` и `localStorage`. Обращения к браузеру выполнять в эффектах, обработчиках или за явной проверкой окружения; очищать подписки, таймеры и анимационные циклы.
- Не заменять текущий клиентский запуск на `hydrateRoot` как случайный рефакторинг: `src/main.tsx` намеренно сохраняет готовый HTML до загрузки страницы, затем монтирует React через `createRoot`.

## Дизайн и удобство

- Развивать существующий образ сайта: тёмный фон, красный `primary`, оранжевый `accent`, Orbitron для заголовков и Inter для текста. Использовать токены из темы; менять общий визуальный язык, когда это входит в задачу.
- Сохранять ясную иерархию, согласованные отступы и читаемую длину строк. Подбирать компоновку под содержание; не превращать каждый абзац в карточку и не добавлять декор без пользы.
- Для проектов использовать реальные обложки и скриншоты, для автора — его материалы. Не подменять портфолио случайными стоками, выдуманными наградами или сгенерированными свидетельствами опыта.
- Делать адаптивную вёрстку: проверять изменённый экран примерно на 360–390, 768 и 1440 px. Не допускать обрезанного текста, наложений, горизонтальной прокрутки всей страницы и кнопок, недоступных на телефоне.
- Действия оформлять кнопками, переходы — ссылками. Сохранять видимый фокус, управление с клавиатуры, подписи полей, осмысленные `alt` и доступные названия кнопок с иконками. Для модальных окон проверять Escape, удержание и возврат фокуса.
- Анимации и кастомный курсор не должны мешать чтению и нажатию. Учитывать `prefers-reduced-motion` и сенсорные устройства; не делать hover единственным способом получить важную информацию.
- Оптимизировать новые изображения под размер показа, резервировать место через размеры или `aspect-ratio`. Медиа ниже первого экрана загружать лениво; главное изображение первого экрана не задерживать ленивой загрузкой.
- После изменения навигации или контактов проверять реальный сценарий: мобильное меню, переход к секции с другой страницы, открытие контактов и закрытие диалога.

## Контент, маршруты и SEO

- Писать конкретно, без рекламной воды. Не придумывать опыт, отзывы, числа, цены, даты релизов и обещания результатов обучения. Брать факты из текущего контента или указаний пользователя; спорные сведения уточнять.
- В авторских текстах использовать первое лицо и живую, спокойную речь. Помогать гостю выбрать между играми, личной историей и менторингом; сохранять различие между собственными играми, вкладом в командные проекты и работами учеников. Не придумывать за автора воспоминания, чувства или мотивы.
- Контактные данные менять через `src/constants/contactLinks.ts` и существующие компоненты. Сохранять используемый механизм раскрытия контактов, не дублировать адреса в новых блоках.
- При добавлении страницы согласованно проверить маршрут в `src/App.tsx`, метаданные, необходимость пререндеринга и начальную загрузку в `src/main.tsx` / `src/entry-server.tsx`. Обработку `*` оставлять последней.
- Использовать `https://gamepunk.ru` как текущий канонический адрес. Сохранять существующие URL и якоря; при их изменении обновлять все связанные переходы.
- Проверять title, description, canonical, Open Graph и robots в итоговом HTML. `sitemap.xml` генерируется из маршрутов и правил индексации; не редактировать его вручную в сборке.
- Сохранять заданный `noindex` служебных страниц. У `/malena/privacy` дополнительно есть исключение аналитики при пререндеринге; не терять его при изменениях общего шаблона.
- Проверять прямое открытие и обновление вложенного URL, а не только переход через React Router. Учитывать `public/404.html` и статический хостинг.
- Основной контент пререндеренных страниц должен оставаться читаемым без JavaScript. Не оставлять его невидимым из-за начального состояния Framer Motion.
- Публичная Академия доступна по `/academy` из основного меню и блока на главной. Сохранять этот маршрут и обратный переход на сайт, в том числе на телефоне. В описании Академии опираться на опубликованные материалы; не загружать весь каталог уроков ради ссылки или анонса на главной.
- При содержательном обновлении курса, урока или подборки Академии обновлять `updated: YYYY-MM-DD` в соответствующем Markdown-файле. Лента «Свежее» учитывает последнюю дату курса и его уроков; общий редизайн и пересборка не меняют дату учебного материала.
- На главной Академии направления остаются выше «Свежего», включая направления, которые ещё заполняются. На телефоне список уроков и оглавление статьи должны быть сворачиваемыми и доступными без JavaScript.
- Каталог Академии содержит только метаданные; тексты загружать через `academyContent` для выбранного материала. Общий разбор маршрута и SEO — в `academyRoutes` / `resolvePageMetadata`; использовать его и при переходах в браузере, и при пререндеринге. Единственный H1 задаёт шаблон страницы, учебный Markdown начинается с текста или H2.

## Absolute Academy Source

- `AbsoluteAcademySource/` — отдельная локальная база сырых и редакционных материалов Академии, а не часть готового сайта.
- При работе над сайтом не читать, не индексировать, не импортировать и не изменять этот каталог, если пользователь явно не попросил использовать материалы Академии.
- Не включать содержимое `AbsoluteAcademySource/` в сборку, `public`, `dist` или страницы сайта автоматически.
- Когда задача явно относится к Академии или конкретному курсу, следовать подробным правилам из `AbsoluteAcademySource/AGENTS.md`.

## Проверка результата

Команды выполнять из корня репозитория. Выбирать проверки по изменению; не запускать весь набор ради исправления только инструкций.

| Изменение / цель | Проверка |
| --- | --- |
| Только `AGENTS.md` или другая документация вне страниц | Перечитать изменения, проверить пути и команды, выполнить `git diff --check` |
| TypeScript / TSX | `npx tsc --noEmit -p tsconfig.app.json` и ESLint для затронутых файлов; для проверки всего `src` — `npx eslint src` |
| Логика, маршруты, поведение компонентов | Затронутые тесты через `npm test -- src/test/имя.test.tsx`; весь набор — `npm test` |
| Код сайта, стили, публикуемый контент, зависимости или сборка | `npm run build` — включает клиентскую сборку, SSR и пререндеринг |
| Интерфейс и взаимодействия | `npm run dev` и проверка в браузере; для итоговой сборки — `npm run preview` |

- `npm run lint` проверяет только `src/`, не заходя в локальные материалы. `npm run check` запускает проверку типов, ESLint и тесты; этот же набор выполняется в CI перед сборкой и публикацией.
- Vite-сборка не заменяет проверку типов. Успешная сборка также не подтверждает исправность кнопок, адаптивность и отсутствие ошибок в браузере.
- Добавлять тесты для нового поведения и воспроизводимых регрессий. Не писать тесты, которые лишь повторяют реализацию, и не добавлять тесты ради простой правки текста или отступа.
- Исправлять ошибки, внесённые своей правкой. Найденные старые проблемы обозначать отдельно; не превращать локальную задачу в непрошеную переделку проекта.
- Перед сдачей просмотреть diff и `git diff --check`, убедиться, что нет случайных файлов. Если проверка недоступна, указать это прямо.

## Git и публикация

- Держать изменения в рамках задачи. Не включать временные файлы, логи, сборки, локальные материалы и секреты в коммит.
- Push в `master` запускает публикацию через `.github/workflows/deploy.yml`. Не считать его обычным сохранением локальной работы.
- Коммит, push и публикацию выполнять, когда это поручено пользователем; уже полученное разрешение повторно не запрашивать. Перед публикацией завершить нужные проверки, после — проверить результат workflow и доступность изменённой страницы.
- Если создаёшь новую ветку, использовать префикс `codex/`, если пользователь не задал другое имя. Не применять разрушительные откаты и принудительный push без явной необходимости и разрешения.
